# 智能客服：项目介绍与面试说明

## 项目背景

面向电商客服中的比价导购、二手鉴定、售后理赔和订单咨询，针对业务知识分散、多版本规则误引、精确信息召回不稳及反馈难以反哺策略等问题，完成具备可信 RAG、Agent Harness、分层 Memory 和反馈自进化 Loop 的电商客服知识助手。

## 解决方案

1. **Agent Harness 编排治理**：采用 `Intent → Rewrite → Retrieval → Answer → Verify` 固定 DAG，pi Agent Runtime 负责模型推理，Python 治理层负责权限隔离、事实校验、超时降级和策略发布，约束 Agent 执行流程。
2. **可信 RAG 与混合检索**：以 MongoDB 为事实平面，维护业务文档的版本链、生效状态、来源哈希与条款元数据；采用 `BM25 + 向量召回 + RRF + 可选 Reranker`，结合电商术语与会话上下文改写查询，回填有效原文并校验引用。
3. **分层 Memory 架构**：划分工作、情景、用户语义、组织知识和程序性策略五类记忆，通过 MemoryContextBuilder 按权限、时效、权威等级和上下文预算组织信息，避免将历史对话或模型推断作为业务事实。
4. **反馈自进化 Loop**：采用 `Execute → Observe → Reflect → Adapt → Deploy` 闭环，将失败归因为检索、意图、生成或知识缺口，形成 Skill／Hook／Rule 候选，支持查询扩展、top-k 调整和模板切换，经 Trace 回放、灰度验证后发布或回滚。

## 项目成果

- 整理7个知识责任组、7份流程知识文档、17条术语与23项专业能力目录，完成业务知识与系统配置。
- 后端59项测试及7条离线场景问答验证通过，覆盖自动路由、来源引用、鉴权、版本治理与记忆等功能。
- 验证售后 Skill 能执行查询扩展、top-k 调整与模板切换，并记录策略执行结果。

## 30秒介绍

我完成了一个面向电商场景的客服知识助手，覆盖导购、鉴定、售后和订单咨询。项目通过固定 Agent 流程、混合检索和来源校验生成可追溯回答，并用分层记忆处理上下文，用反馈与 Skill 管理后续策略。我重点完成业务资料整理、术语与路由配置、场景提示词和策略配置，以及工程验证。当前版本提供文本咨询与流程指引，实时业务操作需要对接授权系统。

## 关键问题

**如何避免编造价格或退款状态？** 先区分流程知识和实时事实；缺少带时间、商品规格或订单身份的授权数据时，说明核验条件和查询渠道，不返回确定的实时结果。

**pi 与 Python 如何分工？** Python 控制固定流程、权限、事实与策略发布，pi 运行获准阶段的模型任务与受控工具调用。

**如何证明 Skill 改变了执行？** 检查扩展后的查询、top-k、模板指令和 strategy_executions。当前售后示例已验证 top-k 从5变为7；质量提升仍需独立数据集评估。

**当前结果的口径是什么？** 59项后端测试和7条场景问答为离线功能验证，不代表真实模型准确率、生产流量或延迟指标。技术组件及工程基础见仓库开发参考说明。
